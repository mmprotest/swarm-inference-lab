# Model and engine support

Swarm is a general-purpose distributed inference runtime for open-weight models. Model
architecture, artifact format, quantization, engine capability, and validation evidence are
separate facts. A checkpoint being recognized does not by itself mean that it has a complete
execution plan.

The resolver derives architecture from `config.json`, `model_type`, `architectures`, nested text
configuration, Safetensors headers/indexes, and GGUF metadata. Repository names are not used for
dispatch. Architecture adapters are registered by implementation family and can be added through
the `swarm_inference.architecture_adapters` entry-point group.

For sharded Safetensors, the resolver validates the immutable index as a tensor-to-shard map and
selects exactly the referenced shards. Missing, malformed, absolute, or parent-traversing targets
fail resolution, and unrelated Safetensors files such as optimizer or training state are not
silently added to the model artifact.

## Status vocabulary

The machine registry uses these non-interchangeable values:

- `SUPPORTED`: the probe found a complete compatible execution path.
- `SUPPORTED_WITH_LIMITATIONS`: a complete path exists with reported restrictions, or only an
  explicitly named component is available for hybrid composition.
- `SOFTWARE_VALIDATED`: deterministic fixture/reference tests executed.
- `REAL_MODEL_VALIDATED`: an immutable real checkpoint executed and retained correctness evidence.
- `PHYSICAL_DISTRIBUTED_VALIDATED`: distinct physical hosts executed the plan.
- `UNSUPPORTED_FORMAT`, `UNSUPPORTED_ARCHITECTURE`, and `UNSUPPORTED_QUANTIZATION`: a precise
  incompatibility was proved.
- `UNAVAILABLE_RUNTIME`: the implementation exists, but no eligible hash-bound runtime/device is
  installed in the inspected swarm.
- `NOT_APPLICABLE`: that engine does not consume the artifact class.
- `NOT_TESTED`: no applicable retained evidence exists. This never means unsupported.

Registry rows are generated by `build_compatibility_registry()` from live engine probes and exact
model/runtime fingerprints. Validation evidence is accepted only when both fingerprints match.

features, quantization, device, and memory required by the artifact. It is not a blanket family
claim. Likewise, a Colibri component result is not a selectable complete-model plan until another
engine supplies attention, KV cache, tokenization, sampling, and any other missing capabilities.

## Current checkpoints and rename-safe discovery

Maintainers can inspect a bounded explicit list without downloading weights:

```powershell
uv run python scripts/inspect_model_compatibility.py `
  Qwen/Qwen3.6-35B-A3B `
  moonshotai/Kimi-K3 `
  zai-org/GLM-5 `
  deepseek-ai/DeepSeek-V3.2
```

The report records immutable identity, architecture profile, format, quantization, modalities,
and adapter capabilities. It deliberately does not claim execution. A renamed or fine-tuned
checkpoint works without a coordinator change when its metadata and tensor layout satisfy an
existing adapter.

## Qwen3.6 format split

`Qwen/Qwen3.6-35B-A3B` identifies the `qwen3_5_moe` hybrid architecture. For the corresponding
Safetensors layout, the generic Colibri adapter supplies routed-MoE components but the complete
hybrid attention/KV path is not yet integrated. For
`unsloth/Qwen3.6-35B-A3B-GGUF`, Colibri and native stage reject GGUF; an installed llama.cpp
runtime may accept the exact quantization only if its capability advertisement proves the
`qwen35moe` loader path.

## Validation policy

Architecture fixtures cover resolution, profile detection, format separation, tensor roles,
expert descriptors, shard/reduction semantics, engine probing, registry output, and planning.
Generic Colibri numerical tests compare routing and separate/fused SwiGLU expert computation.
The optional native component gate loads the built ABI v2 library and compares FP32, BF16, and
packed symmetric INT4-G32 execution with deterministic numerical references. Passing it validates
the component binary only, not attention/KV integration or whole-model generation.
Heavyweight real-model and physical-distributed gates are opt-in and remain `NOT_TESTED` unless
an executed, hash-bound evidence bundle is supplied. Historical experiment results are never
silently promoted to a different architecture or artifact.
